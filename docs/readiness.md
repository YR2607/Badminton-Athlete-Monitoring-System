# Алгоритм расчёта готовности

Файл: `src/lib/readiness.ts`. Реализация прозрачная и детерминированная —
никаких ML-моделей и медицинских прогнозов. Показатель — **субъективный
индекс утреннего самочувствия 0–100**, а не оценка готовности к
соревнованиям и не медицинский допуск.

## Нормализация

Каждый ответ анкеты 1–10 приводится к 0..1, где **больше = лучше**:

| Показатель | Направление | Формула |
|---|---|---|
| sleep_score | прямой | (v−1)/9 |
| recovery_score | прямой | (v−1)/9 |
| fatigue_score | инвертирован | (10−v)/9 |
| muscle_soreness_score | инвертирован | (10−v)/9 |
| stress_score | инвертирован | (10−v)/9 |
| mood_score | прямой | (v−1)/9 |

## Итоговый балл (утреннее самочувствие)

Взвешенное среднее нормализованных компонентов × 100:

```
sleep 0.20 · recovery 0.25 · fatigue 0.20 · soreness 0.15 · stress 0.10 · mood 0.10
```

Это **рабочая эвристика**, а не вероятность травмы. Первичные ответы хранятся
в `morning_checkins`; производные — в `readiness_snapshots` (по одному снимку
на день, upsert по `(athlete_id, snapshot_date)`).

## Утро и вечер — строго раздельно

Утреннее самочувствие (`morningWellnessScore`, серия `dailyReadiness`) —
единственное, что входит в балл готовности, снапшоты и личную норму.

Вечерняя анкета — **отдельный показатель** «отклик на тренировку»:

```
post_wellness = mean( overall_feeling , inv(leg_fatigue) , inv(arm_shoulder_fatigue) ) × 100
```

Она не смешивается с утренним баллом и не участвует в норме
(`postWellnessScore` / `dailyPostResponseSeries`, бакетирование —
`postsByLocalDate`: последняя анкета за локальный день, привязка к дате
сессии через `training_session_id`).

## Личная норма (`personalNorm`)

Единый источник сравнения «сегодня vs своя история» для снапшотов, алертов
и дашборда. Сегодняшний день всегда исключён из окна:

1. **Rolling-норма** — последние 28 дней, минимум 10 наблюдений, SD с полом
   `SD_FLOOR_SCORE = 3`. Предпочтительна, когда данных хватает.
2. **Начальная норма** — первые ≤14 дней с данными, минимум 8 наблюдений
   (`MIN_BASELINE_OBSERVATIONS`), пока rolling ещё не сформирован.
3. **Нет нормы** — данных мало: показывается «недостаточно данных»,
   произвольных сравнений не делается.

Пропуски дней не заполняются нулями — пропущенные даты просто отсутствуют.

## Объяснение (explanation jsonb)

- `band`: good ≥ 70, moderate ≥ 45, low < 45.
- `flags`: `below_personal_baseline` (z > 1.0 ниже нормы ИЛИ абсолютное
  падение ≥ 15 при sd = 0), `low_<component>` для компонентов ≤ 0.25.
- `delta_vs_baseline`: разница с личной нормой в пунктах.

## Рекомендации спортсмену

Тексты берутся из словаря по band: good → «тренируйся по плану»,
moderate → «снизь интенсивность, скажи тренеру», low → «обязательно скажи
тренеру». Таблица `recommendation_texts` содержит переводы ru/ro/en.

## Статус спортсмена на панели тренера

`src/lib/athlete-status.ts` → `athleteStatus()`. Статус выводится из реальных
данных и существующих сигналов, по убыванию приоритета:

| Статус | Условие |
|---|---|
| `needs_check` | открытый приоритетный алерт ИЛИ acute-флаги в сегодняшних анкетах (нестабильность, отёк, ограничение движения, боль ≥ 7, симптомы) |
| `declining` | сегодняшний балл ниже личной нормы (>1·sd или ≥15 п.) ИЛИ открытый алерт «ухудшения» (readiness_drop, sustained_decline, repeated_fatigue, joint_pain) |
| `no_today` | утренней анкеты за локальный «сегодня» спортсмена нет — состояние неизвестно, старый балл не показывается как текущий |
| `insufficient` | анкета есть, но норма ещё не сформирована |
| `ok` | актуальные данные есть, активные правила сигналов не дали — это НЕ медицинское «всё хорошо» |

Поверх статуса — категории приоритета (`src/lib/priority.ts` →
`classifyAthlete()`), взаимоисключающие, по приоритету: **check** (острые
флаги) → **review** (ухудшение/ниже нормы/боль) → **missing** (нет анкеты,
норма не сформирована, нет вечерней анкеты, пропущенная тренировка) →
**none** (нет сигналов — не допуск).

Принципы: тревожный сигнал не маскируется высоким баллом; вывод об ухудшении
не делается без сегодняшней оценки (кроме уже открытых алертов); отсутствие
анкеты — это качество данных, а не состояние. «Сегодня» считается в часовом
поясе каждого спортсмена.

Качество данных отображается отдельно: дата и возраст последней анкеты,
число наблюдений для нормы, зарегистрированные тренировки, незаполненные
post-анкеты (`pendingPostCheckins`). «Пропущенная тренировка» показывается
только при активном расписании группы (`scheduledMissedYesterday`); без
расписания — только «нет записи».

## Сессии и нагрузка

Запись `training_sessions` создаётся автоматически при отметке
присутствия в посещаемости (из плана группы) или при отправке вечерней
анкеты как маркер «тренировка была». `duration_minutes`, `session_rpe`
могут быть NULL — тогда сессия засчитана, но нагрузка **не известна**.

`src/lib/load.ts` → `dailyLoads()` различает состояния дня (`state`):

- `known` — все записанные сессии с RPE и минутами → `load` = Σ rpe×мин;
- `partial` — сессии есть, но часть без параметров → реальная нагрузка
  неизвестна (в `load` только квантифицированная часть);
- `unknown` — тренировка планировалась или посещаемость «был», а записи
  нет → это **не** ноль;
- `rest` — день без занятия по плану или посещаемость «не был/уважительно».

`loadCoverage()` — доля дней с достоверной нагрузкой (`known|rest`).
ACWR (EWMA 7/28), monotony и связанные алерты/рекомендации срабатывают
только при покрытии ≥ 80% — неполные данные не превращаются в уверенный
вывод. ACWR 0.8–1.3 — ориентировочная зона, не «безопасная» и не прогноз
травмы.

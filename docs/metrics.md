# Метрики и формулы

Формулы считаются на сервере (`src/lib/`), клиент только отображает.
Источники — в конце файла. Пороги правил настраиваются в `/admin/rules`.

## Анкеты

- Утренняя: 6 шкал 1–10 (сон, восстановление, усталость, мышцы, стресс, настроение).
- Вечерняя (после тренировки): 3 шкалы 1–10 + **sRPE-поля** (см. ниже, за флагом `srpe`).
- Балл анкеты 0–100: нормализация `(v−1)/9`; веса — сон .20, восстановление .25,
  усталость .20, мышцы .15, стресс .10, настроение .10.
- Балл дня = 0.7 × утренняя + 0.3 × вечерняя.

## Нагрузка (sRPE, Foster) — флаг `srpe`

- Вечерняя анкета собирает `session_rpe` (CR-10, 0–10 с вербальными якорями) и
  `session_minutes` (по умолчанию — план из расписания группы).
- `training_sessions.session_load` = `session_rpe × duration_minutes` (generated column).
- `daily_load` = Σ session_load за локальный день спортсмена. День без тренировки
  по расписанию — 0 («отдых»); день по расписанию без данных — `hasData=false`
  («нет данных»).
- Дозаполнение: вчерашнюю тренировку можно заполнить до конца следующего дня;
  анкета привязывается к дате сессии, а не ко времени отправки.

### ACWR (EWMA, Williams et al. 2017)

- `acute` = EWMA(daily_load, λ=2/8) — ~7-дневное окно.
- `chronic` = EWMA(daily_load, λ=2/29) — ~28-дневное окно.
- EWMA инициализируется первым наблюдением (steady state читается сразу).
- `ACWR = acute / chronic`; показывается при ≥21 дне истории и chronic ≥ 1.

### Монотонность и strain (Foster)

- `monotony` = mean(daily_load за 7 дн.) / population-SD; null при SD≈0.
- `strain` = сумма недели × monotony.

### План против факта

- Расписание группы хранит `planned_minutes` и `planned_rpe` →
  `planned_load` = их произведение (суммируется при нескольких слотах в день).

## Новые правила алертов

| Код | Параметры (default) | Условие |
|---|---|---|
| `acwr_high` | threshold 1.5, min_days 21 | ACWR > порога |
| `acwr_low` | threshold 0.8, min_days 28 | ACWR < порога (информационный) |
| `monotony_high` | threshold 2.0 | монотонность 7 дней > порога |
| `plan_deviation` | ratio 1.25, sessions 3 | факт > план × ratio — N дней подряд |

## Фиче-флаги

`feature_flags` (key, enabled, group_ids): `enabled` + пустой `group_ids` =
включено для всех; непустой список = только спортсмены этих групп.
Управление — `/admin/features`.

## Личные z-score нормы (Фаза 2, флаг `zscore_baseline`)

- **Скользящая норма**: среднее и SD за последние **28 дней, не включая сегодня**,
  для итогового балла и каждого пункта утренней анкеты отдельно.
- Минимум данных: **10 заполненных дней** — иначе норма считается не сформированной
  и работает старый абсолютный порог (`sd_below` / `min_abs_drop`).
- **Нижний предел SD**: 3 балла (из 100) для итогового балла, 0.5 балла (из 10)
  для отдельных пунктов — чтобы «стабильный» спортсмен не получал ложные сигналы.
- `z = (сегодня − норма) / SD`. Зоны: z ≥ −1 — норма; −1.5 < z < −1 — внимание;
  z < −1.5 — сигнал `readiness_drop` (порог `z_below` настраивается в правилах).
- Нормы и z-оценки сохраняются в `readiness_snapshots.z_score`,
  `item_baselines`, `item_zscores` — дашборд (Фаза 7) читает их напрямую.
- Утренняя анкета дополнена полем **«часы сна»** (`sleep_hours`, шаг 0.5,
  опционально, за флагом) — существующая шкала сна не менялась.

## Рост и созревание — Khamis-Roche (Фаза 4, флаг `growth`)

- Замеры: `growth_measurements` (дата, рост см, вес кг, опц. рост сидя) — вводит
  тренер/админ, уникально по дню. Поля спортсмена: `birth_date`, `sex`,
  `mother/father_height_cm` — только с согласия родителей.
- **PAH (Khamis-Roche 1994)**: возраст округляется до 0.5 года, таблица
  коэффициентов (4.0–17.5) взята дословно из пакета matuR
  (`data/table.rda`); формула в дюймах/фунтах:
  `PAH = β + h×βh + w×βw + midparent×βm`. Контрольные примеры — в тестах.
- **%PAH** = рост/PAH×100. Категории: ≤87% до скачка, 88–95% скачок,
  >95% после (пороги настраиваются в правиле `growth_spurt`).
- **Скорость роста** = Δрост/Δгод по двум последним замерам (мин. ~2 мес.).
- Алерт `growth_spurt` (параметры band_low/band_high/velocity_cm_yr) и
  рекомендация `growth_spurt` (ограничить прыжки, техника приземления).

## Рекомендации (Фаза 8, флаг `recommendations`)

- Таблица `recommendations` (athlete, дата, rule_key, severity, inputs,
  decision). Только тренер/админ; спортсмен не видит.
- `evaluateRecommendations` (src/lib/recommendations.ts): матрица
  z×ACWR×просевшие пункты; `rest_medical` и `growth_spurt` перекрывают всё.
- Тренер отмечает принято/изменено/отклонено + комментарий (аудит).
